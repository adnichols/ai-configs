Herdr Pi State Reconciliation Plan

Make the repo-managed Herdr Pi extension report pane state from the full Pi work lifecycle, including genuine Pi subagents and lost final state reports, without letting passive plan/PR monitor processes keep panes working forever.

Goal

Fix incorrect Herdr state reporting for Pi sessions where:

  • the parent Pi turn completes while background subagents are still running, causing Herdr to show completed too early;
  • Herdr stays working after work is complete because the final idle report was dropped or missed;
  • blocked prompts and retry holds must continue to take precedence over ordinary idle/working transitions;
  • passive background monitors for plans, PRs, logs, or review comments must not prevent Herdr from reporting idle/done.

Current Evidence

Primary file: _pi/extensions/herdr-agent-state.ts

Installed copy: ~/.pi/agent/extensions/herdr-agent-state.ts currently matches the repo copy.

Relevant subagent source: /Users/anichols/.pi/agent/npm/node_modules/@tintinweb/pi-subagents/src/index.ts and src/agent-manager.ts.

The Herdr extension currently tracks parent Pi lifecycle events, blocked state, retry holds, socket send retry, and a one-way stale-working watchdog. It does not consume the Pi subagents event stream or the subagent manager registry.

The Pi subagents extension already emits subagents:created, subagents:started, subagents:completed, and subagents:failed. It also exposes globalThis[Symbol.for("pi-subagents:manager")] with hasRunning() and getRecord(id). hasRunning() is the authoritative manager signal for this plan because it reports only Pi subagent records with status === "running" || status === "queued"; passive process-tool monitors are tracked outside the Pi subagents registry.

Root Cause

The current Herdr integration treats the parent Pi agent_end event as sufficient evidence that the pane can become idle. That is false when the parent turn spawned background subagents.

  1. Parent Pi agent starts background subagents.
  2. Parent turn ends and emits agent_end.
  3. Herdr extension sets agentActive = false and schedules idle.
  4. Subagents continue running, but Herdr has no state source for them.
  5. Later subagent completion may trigger a follow-up turn, making the pane appear to go working after it had already been reported complete.

Scope

In scope

  • Add subagent lifecycle awareness to _pi/extensions/herdr-agent-state.ts.
  • Use the subagent manager as the authoritative running/queued signal when available, filtered to blocking agent work.
  • Do not count passive plan-review, PR-monitor, log-tail, watch, or shell listener processes as blocking work.
  • Replace one-way reconcile with full desired-state reconciliation.
  • Add session-boundary cleanup so late subagent events or heartbeat ticks cannot publish working after session_shutdown.
  • Add a low-frequency heartbeat to re-send current state when Herdr missed or dropped reports.
  • Keep behavior unchanged when the subagents extension is absent.

Out of scope

  • Changing the Herdr daemon protocol.
  • Changing the Pi subagents package.
  • Adding durable state outside this runtime extension.
  • Reworking Herdr's terminal-screen fallback heuristics.

Counting Rules

Herdr state should represent whether the Pi agent still has user-requested agent work in flight, not whether every auxiliary background process is alive.

P1: Add Subagent-Aware State Source

Implementation

  • Add local fallback tracking with const subagentIds = new Set<string>().
  • Subscribe to pi.events.on("subagents:created") and pi.events.on("subagents:started") to add IDs and publish working.
  • Subscribe to pi.events.on("subagents:completed") and pi.events.on("subagents:failed") to remove IDs and schedule/publish the next desired state.
  • Add safe manager lookup that uses hasRunning() as the primary authoritative signal when available.
  • Optionally use getRecord(id) for locally tracked IDs during diagnostics or future filtering; do not depend on unavailable listAgents().
  • Document that passive plan/PR/log/watch monitors are excluded because they are process-tool work, not Pi subagent records.
function managerBlockingSubagentsRunning(): boolean | undefined {
  const manager = (globalThis as any)[Symbol.for("pi-subagents:manager")];
  if (typeof manager?.hasRunning !== "function") return undefined;
  return manager.hasRunning() === true;
}

Notes

Subagent events are fast-path triggers. The manager is the stronger signal when present because it covers running and queued agents and self-heals missed events. subagents:created is a background-agent creation signal; subagents:started is the reliable add signal for both foreground and background subagents, including queued agents that later begin running.

P3: Replace One-Way Reconcile and Add Session Cleanup

The current reconcile watchdog only fixes stale working -> idle. Replace it with full desired-state reconciliation, and make all new timers/state session-scoped so shutdown cannot publish stale work after the pane is released.

  • If manager.hasRunning() reports no running/queued subagents, clear stale local subagent IDs.
  • If manager.hasRunning() reports running/queued subagents, never force idle just because parent ctx.isIdle() is true.
  • If passive monitor processes are still running but no blocking subagents remain, allow idle/done.
  • Recompute desiredState() every interval.
  • Publish when the authoritative desired state differs from the last reported state.
  • Keep parent ctx.isIdle() and ctx.hasPendingMessages() as parent-turn checks, not as global pane-idle authority.
  • On session_shutdown, stop reconcile, stop heartbeat, clear idle/retry timers, clear parent/retry/blocked state, clear subagentIds, disable and drain queued state reports, mark the root session inactive before releasing the pane, and ignore late subagent events when no active root session exists.
  • Use a session-generation token for queued state reports, retry-hold timer promotion, and shutdown release so an older async callback cannot release, retry, or block a newer session.

P4: Add Heartbeat Republish

Add a low-frequency heartbeat so Herdr can recover when the final idle or working report is dropped after send retries are exhausted.

Configuration

  • HERDR_PI_HEARTBEAT_MS, default 15000.
  • 0 disables heartbeat.

State to track

let lastPublishAt = 0;
let lastSuccessfulStateReportAt = 0;
let lastQueuedState: AgentState | undefined;
let lastQueuedMessage: string | undefined;

Behavior

  • Update lastPublishAt whenever a state is queued.
  • Update lastSuccessfulStateReportAt only when sendState(...) succeeds.
  • On heartbeat, recompute desired state and force-publish if lastSuccessfulStateReportAt < lastPublishAt or if no successful report has occurred within the heartbeat interval.
  • Heartbeat republish should use the same state queue and sequence mechanism as normal state reports.
  • Heartbeat must not bypass blocked or subagent-running checks.
  • Heartbeat must stop on session_shutdown and must check the active root session guard before queueing any state.

P5: Verification

Manual scenarios

  1. Spawn one background subagent; parent turn ends; Herdr remains working until the subagent completes.
  2. Spawn multiple parallel subagents; Herdr stays working until the last subagent completes.
  3. Queue a subagent behind the max concurrency limit; Herdr treats queued work as working.
  4. Simulate missed completion or stale local ID; reconcile clears it when manager reports no running/queued agents.
  5. Temporarily break Herdr socket during final idle; heartbeat republishes idle after connectivity returns.
  6. Start a passive plan-review agent next --wait listener or PR monitor after active work completes; Herdr may report idle/done while the listener remains alive.
  7. Run without the subagents extension; behavior remains parent-agent-only.
  8. Shut down or switch sessions while parent, blocked, retry, subagent, queued-report, or heartbeat state exists; the next session starts from fresh state and no late callback republishes working or blocked.
  9. Trigger a blocked prompt while work is active; blocked state still wins over working/idle.

Static checks

Run the repository's install validation relevant to Pi extensions if available. At minimum, reload Pi after installing and verify TypeScript syntax through Pi extension loading.

Acceptance Criteria

  • Herdr does not report idle/completed while blocking Pi subagents are running or queued.
  • Herdr reports idle after the parent agent and all blocking subagents are complete, even if passive plan/PR monitor processes remain alive.
  • Missed subagent events self-heal through the subagent manager lookup.
  • Dropped final state reports self-heal through heartbeat republish.
  • Blocked and retry states preserve their existing priority.
  • No-subagents environments retain existing behavior.
  • Session shutdown clears parent state, blocked/retry state, subagent fallback state, queued reports, and heartbeat/reconcile timers before pane release, preventing stale working reports after release or into the next session.
