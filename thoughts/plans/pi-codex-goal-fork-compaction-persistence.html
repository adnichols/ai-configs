Goal

Use Aaron's GitHub fork of pi-codex-goal as the managed install source, patch the fork so active goals survive pi-vcc in-flight compaction as active goals, and update ai-configs so ./install.sh --pi installs the fork instead of the upstream npm package.

The desired outcome is Codex-like persistence: after compact_context or pi-vcc threshold compaction interrupts an in-flight turn, the goal should continue automatically or at least remain active. It must not silently degrade to Goal paused (/goal resume) unless the user actually aborted, the agent paused for a real blocker, the goal completed, or a non-retryable provider/recovery failure occurred.

Decision Attention / Low-confidence Areas

D1 — adnichols is a GitHub user account, not an org. gh repo fork --org adnichols failed because GitHub reports adnichols as a user login. The fork now exists at adnichols/pi-codex-goal. Treat the user's “adnichols gh org” wording as the desired owner namespace.

D2 — Prevent duplicate goal packages. ai-configs must remove or avoid npm:pi-codex-goal when installing git:github.com/adnichols/pi-codex-goal. Leaving both risks duplicate slash commands/tools such as /goal, get_goal, create_goal, and update_goal.

D3 — Continuation ownership is explicit. For pi-vcc interrupted in-flight compaction, pi-vcc owns the next-turn trigger and pi-codex-goal must only preserve active goal state while suppressing its own post-compact continuation. For non-pi-vcc compaction, pi-codex-goal keeps its existing continuation ownership. Tests must prove exactly one bounded continuation path per compaction event.

D4 — Publishing path is not required for first rollout. The requested install source is a GitHub fork, so this plan uses git:github.com/adnichols/pi-codex-goal. Do not publish an npm package unless a later user decision requests npm distribution.

D5 — The installed ref is fork main. Because the ai-configs source is the unqualified GitHub fork package, P2 must fast-forward adnichols/pi-codex-goal main to the tested patch before P3/P4. Do not proceed with ai-configs rollout while the patch exists only on an uninstalled branch.

Why this plan exists

In test-e2e-hub, session JSONL showed active pi-codex-goal state being persisted as paused immediately around pi-vcc compaction. pi-vcc then sent its generic continuation prompt, so the agent kept working but the goal footer/state remained Goal paused (/goal resume). That defeats the purpose of persistent long-running objectives.

The root cause is the current pi-codex-goal abort policy: it suppresses pause only for compactions it started itself via proactiveCompactionPending. pi-vcc compaction is externally initiated, so the aborted in-flight assistant turn is treated like a user abort and the goal is paused.

Product intent alignment

This is an agent workflow reliability change. The golden path is an agent working under an active /goal through normal pi-vcc compaction. Compaction is a routine recoverable event; it should self-heal inside the normal goal loop, not require a human to notice a footer state and type /goal resume.

Safe default: compaction-triggered aborts are not user aborts. Fail closed only when the abort is not associated with a known compaction lifecycle event, when the user presses Escape, or when provider recovery reaches a bounded failure condition.

UI impact: text-only/operator-facing. Runtime status changes from misleading Goal paused to truthful active pursuit after compaction. ai-configs docs and verification output change from npm package source to GitHub fork source.

Locked decisions

  • Install source: git:github.com/adnichols/pi-codex-goal, resolving to fork main.
  • Patched ref requirement: fork main must contain the tested compaction persistence patch before P3 installs or P4 rollout begin.
  • No npm publication in this plan. GitHub fork install is sufficient for managed local rollout.
  • No duplicate package registrations. The installer must remove or replace npm:pi-codex-goal.
  • Patch the goal plugin first. Do not hide the problem by adding a pi-vcc-only workaround that sends /goal resume.
  • Preserve real abort semantics. User Escape/manual abort still pauses the active goal.

Acceptance criteria

  1. The adnichols/pi-codex-goal fork main branch contains the tested patch proving externally initiated compaction does not pause an active goal, and git ls-remote confirms the installed ref resolves to that commit.
  2. When session_before_compact/session_compact occurs during an active in-flight goal turn, the goal remains active after compaction.
  3. When an assistant turn is aborted without a compaction lifecycle event, the goal still transitions to paused.
  4. After pi-vcc interrupted in-flight compaction, pi-codex-goal preserves active goal state but does not queue its own duplicate continuation; after non-pi-vcc compaction, existing pi-codex-goal continuation behavior remains bounded to one queued continuation.
  5. ai-configs ./install.sh --pi installs git:github.com/adnichols/pi-codex-goal and removes/replaces npm:pi-codex-goal.
  6. ai-configs verification expects the fork source and reports the upstream npm package as stale or missing when appropriate.
  7. ai-configs docs describe the forked install source and why it is pinned.
  8. At least the current Dever environment is updated and verified with pi list; MBP is updated too or blocked with exact access/manual remediation details.

P2: Patch pi-codex-goal compaction handling

End State

The fork distinguishes compaction-caused aborts from real user/provider aborts. Active goals remain active through pi-vcc in-flight compaction and continue in a bounded, non-duplicative way.

Tests first

Add or extend runtime handler tests before code changes. The RED test should reproduce the observed bug: active goal + external compaction + aborted assistant turn currently persists paused.

Work

  1. Add a runtime state field such as externalCompactionPending or a generalized compactionPending with source/reason metadata, the current turn/agent sequence if available, and whether the compacting extension is pi-vcc.
  2. Set the flag in onSessionBeforeCompact when the current goal is active. Prefer session lifecycle reality for pause suppression, but preserve event.compactionEntry.details.compactor === "pi-vcc" when present so continuation ownership can avoid pi-vcc duplicates.
  3. In turn and agent handlers, suppress pauseForAbort only for the aborted assistant/agent event that matches the pending compaction sequence, mirroring the existing proactiveCompactionPending suppression without making the guard global.
  4. Clear the flag on matching session_compact, session_shutdown, after the first matching abort suppression, and on the next non-matching assistant/agent completion. Add a stale-guard regression proving a later user Escape/manual abort still pauses if no matching compaction completes.
  5. On session_compact, apply the fixed continuation rule: for pi-vcc interrupted in-flight compaction where pi-vcc will send its generic continuation, suppress pi-codex-goal's own post-compact continuation; for non-pi-vcc compaction, keep existing bounded pi-codex-goal continuation scheduling.
  6. Keep non-compaction abort behavior unchanged.
  7. Update README/CHANGELOG in the fork with the compaction persistence fix and the pi-vcc continuation ownership boundary.
  8. Push the branch to adnichols/pi-codex-goal, then merge or fast-forward fork main to the tested patch. P3 may not begin until git ls-remote confirms fork main resolves to the tested commit.
