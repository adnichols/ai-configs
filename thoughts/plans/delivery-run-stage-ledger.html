Product-owner context

Agent development already has strong skills for planning, review, implementation, and PR creation. What is missing is a single place that answers: for each worktree, where are we in the process, what evidence do we have, and what should happen next?

Hard gates are intentionally out. A broken optional check must never force the operator to disable the whole workflow. The system should make the right next step obvious and record gaps honestly, while still letting work continue.

What's new

Per-worktree delivery board without hard blocks

Promise: every active delivery worktree can keep a durable stage ledger and appear on one board, with recommended next skills and soft advisories.

  • Before: process lived in long skill prose; progress was scattered across panes, git, Doct, and validation markdown.
  • After: delivery init/show/board/stage/record/check plus a delivery-run skill that orchestrates existing skills as guidance.
  • Observable result: delivery board lists worktrees by stage; delivery check prints advisories and never hard-blocks continuation.
  • Preserved: existing reviewed-html-plan, run-plan, autoreview, PM, and QA skills remain the real workers.

Goal

Ship a v0 delivery stage ledger and skill that make the existing development cycle more automated, deterministic, and visible — using guidance and checks/balances, not required gates.

Locked decisions

  1. Guidance, not gates. Missing recommended evidence becomes an advisory/gap in the ledger. Stage transitions always succeed. No command may refuse continuation solely because a recommended check is incomplete.
  2. Do not reimplement workers. Planning, coding, review, PM, and QA stay in existing skills. Delivery-run records state and points to the next skill.
  3. Ledger lives in the worktree at .delivery/ledger.json. Board scan covers cwd and ~/.herdr/worktrees/*/*/.delivery/ledger.json.
  4. Soft quality inserts in v0: recommended completion eval, PM/customer-impact matrix notes, and conditional adversarial QA prompts are structured fields + check advisories, not blockers.
  5. Optional Herdr label sync. Best-effort only; failure never breaks delivery commands.
