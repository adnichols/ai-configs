Migrate Pi Orchestration to pi-subagents

Replace @tintinweb/pi-subagents with nicobailon’s mainstream pi-subagents extension, expose only the repository’s custom agent catalog, migrate orchestration prompts and runtime integration points, and verify the installed Pi surface without running both general-purpose systems side by side.

Estimated implementation size: one focused change, approximately 25–35 maintained files plus tests and this plan. The 38 active custom agent bodies remain substantially intact; the risk is orchestration and installation semantics, not persona rewrites.

UI impact: no application UI. Pi’s agent/tool list, slash-command behavior, async status, and installer output are operator-facing surfaces and require installed-runtime smoke evidence.

Product-owner context

Situation. The current general-purpose extension is @tintinweb/pi-subagents. It supplies the Agent, get_subagent_result, and steer_subagent tools and also contributes a built-in uppercase Explore agent pinned to Claude Haiku 4.5. That bundled role is the source of unexpected Haiku exploration runs.

User intent. Standardize on the more widely adopted nicobailon extension while continuing to use only repository-owned agent definitions. Extension-provided agent personas, skills, and prompt templates must not silently enter the active catalog. The repository-owned Explore persona has been removed; a minimal Explore.md file containing only enabled: false remains temporarily to disable tintinweb's bundled Explore persona. Isolated discovery is provided by the separately installed @howaboua/pi-explore-subagents extension.

Why the migration is worthwhile. pi-subagents provides one structured subagent tool for single, parallel, chain, async, status, and management operations; a dedicated subagent_wait primitive; child-process crash isolation; explicit fresh/fork context; durable run artifacts; and a cleaner representation of the existing multi-reviewer fan-outs.

DimensionExpected result
CorrectnessNo extension-provided agent can unexpectedly select Haiku or another unapproved model; custom frontmatter remains the model source of truth.

PerformanceIndividual child startup may be slower because children are separate Pi processes; fan-out coordination becomes simpler and less error-prone.

CompatibilityCustom role names and substantive prompts remain stable. Maintained Pi callers move to the new tool contract in one cutover.

Goal

Make pi-subagents the sole general-purpose Pi subagent orchestration extension managed by this repository, disable and filter all of its bundled personas/skills/prompts, preserve the repository’s 38 active custom agents and intended model/reasoning assignments, keep isolated discovery on the dedicated explore_subagent tool, migrate maintained Pi workflows to subagent/subagent_wait, and prove the source and installed surfaces are coherent and recoverable.

Decision Attention / low-confidence areas

No blocking product decision remains. The plan adopts a single cutover, no dual-running transition, built-ins disabled, package skills/prompts filtered, and custom agents retained. Browser review should challenge implementation detail, not reopen the selected product direction without new evidence.
  • Specialized explore tool: retain @howaboua/pi-explore-subagents as the sole intended Explore implementation. It exposes the separately named explore_subagent tool with user-controlled shallow/deep Codex configuration and does not become the general-purpose agent catalog.
  • Async semantics: nicobailon’s current guidance prefers async launches. Deterministic review/PRD commands that must finish in the same invocation will launch one async group and explicitly call subagent_wait({ id }); they must not return a premature success.
  • Frontmatter compatibility: reasoningEffort is not the target schema. Convert it to thinking. Remove mode: subagent and hardcoded tintinweb extension paths. Preserve other fields unless an installed smoke test proves they are invalid.
  • Historical transcripts: pi-vcc should continue recognizing old Agent/get_subagent_result records so compaction of existing sessions does not lose evidence, while new fixtures cover subagent/subagent_wait.

Target workflow and configuration contract

Golden path: an operator runs ./install.sh --pi. The installer removes tintinweb, installs or updates nicobailon, normalizes the package entry so only its extension loads, sets built-ins disabled while preserving unrelated settings, copies the custom agents, and finishes with documentation and verification aligned to the actual state.

{
  "packages": [
    {
      "source": "npm:pi-subagents",
      "skills": [],
      "prompts": []
    }
  ],
  "subagents": {
    "disableBuiltins": true
  }
}

The package entry intentionally omits extensions, so Pi loads the package’s extension. Empty skills and prompts arrays suppress package-provided orchestration guidance. Existing unrelated subagents keys and package entries must survive normalization.

Recovery path: rerunning ./install.sh --pi is idempotent and heals a stale tintinweb registration, a string-form unfiltered npm:pi-subagents entry, missing disableBuiltins, or stale copied custom agents. The verifier reports the exact missing/stale property and rerun command.

Fail-closed boundary: if settings are malformed or cannot be safely merged, do not replace the file with defaults. Stop with the path, parse/shape problem, and exact backup/repair guidance.

Locked decisions

  1. One general-purpose orchestrator. Do not install tintinweb and nicobailon together beyond the brief package-manager replacement operation.
  2. No bundled agent catalog. Set subagents.disableBuiltins: true. The repository’s custom agents remain available, including names that coincide with upstream built-ins.
  3. No bundled package guidance. Store npm:pi-subagents in object form with skills: [] and prompts: []; omit extensions.
  4. Preserve custom model policy. Convert reasoningEffort to thinking; do not alter model IDs or caller-side reasoning policy. There is no custom Explore model assignment after the preparatory removal.
  5. Remove obsolete frontmatter. Remove mode: subagent and all @tintinweb/pi-subagents extension paths. Omitted extensions restores normal extension discovery.
  6. Explicit context. Independent reviewers/researchers use context: "fresh" with self-contained task packets. Use context: "fork" only where a maintained workflow intentionally depends on the parent transcript.
  7. Single fan-out call. Convert each fixed reviewer fan-out to one subagent({ tasks: [...], concurrency: N, async: true }) call and one subagent_wait({ id }) join.
  8. No premature workflow completion. Review and PRD commands that promise integrated output must wait for all required children and fail visibly on missing/failed results.
  9. Historical vcc compatibility. Retain recognition of old tool names in pi-vcc while making the new tool/result shapes first-class in tests and comments.
  10. Specialized exploration stays separate. Retain @howaboua/pi-explore-subagents and its explore_subagent tool for this migration; do not route general review/implementation workflows through it.
  11. No custom fork. Consume released npm:pi-subagents; do not vendor or patch upstream unless implementation discovers a concrete blocker and returns for a new decision.

BDD scenarios

BDD1 — Fresh install exposes only custom agents

Given a new Pi agent directory, when ./install.sh --pi completes, then nicobailon’s extension is registered with bundled skills/prompts filtered, built-ins disabled, and the 38 active custom definitions copied.

BDD2 — Existing tintinweb host self-heals

Given settings contain tintinweb and no nicobailon entry, when the installer runs, then tintinweb is removed, nicobailon is installed and filtered, built-ins are disabled, unrelated settings remain, and the verifier reports clean state.

BDD3 — Unfiltered nicobailon entry is normalized

Given settings contain string-form npm:pi-subagents, when the installer reruns, then the entry becomes object form with empty skills/prompts and no duplicate source.

BDD4 — Unexpected upstream persona cannot run

Given upstream bundles oracle and delegate but the repo does not define those names, when agent discovery runs, then those personas are absent because built-ins are disabled.

BDD5 — Explore discovery uses the dedicated package

Given the repository-owned Explore persona has been removed, tintinweb's bundled persona is disabled by the exact-case Explore.md override, and nicobailon built-ins will be disabled after cutover, when installed agents and tools are inspected, then no general-purpose Explore role or Haiku 4.5 mapping appears and the explore_subagent tool is available from @howaboua/pi-explore-subagents.

BDD6 — Parallel plan review completes before synthesis

Given a plan review invokes GPT and Kimi reviewers, when the command runs, then both tasks launch in one parallel run, the parent waits for that run, and synthesis starts only after both required results are terminal and available.

BDD7 — Seven-way PRD review preserves role parity

Given the seven existing PRD reviewer roles, when review starts, then all seven custom names, task boundaries, output expectations, and completion accounting are preserved under one bounded parallel group.

BDD8 — Child failure is actionable

Given one required reviewer fails or times out, when subagent_wait returns, then the parent reports the failed role/run and recovery action instead of claiming integrated review success.

BDD9 — Compaction preserves active and completed evidence

Given a transcript contains subagent and subagent_wait calls/results, when pi-vcc compacts it, then material task/result evidence remains in the summary and protected-tool logic does not discard it.

BDD10 — Malformed settings fail closed

Given settings.json is malformed or has an incompatible root shape, when migration runs, then it does not overwrite user state and prints the file path and exact repair/rerun guidance.
