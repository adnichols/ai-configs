Pi VCC Semantic Compaction Plan

Plan to improve the vendored Pi VCC compaction extension. The strategy keeps VCC as the default compactor while adding model-driven semantic timing, selective upstream fixes, and DCP-style pruning. Commit-aware durable context is deferred.

Goal

Improve the vendored Pi VCC compaction path while preserving its core strengths: deterministic algorithmic summaries, no extra LLM call, searchable raw-history recall, final redaction, and safe in-flight continuation.

The recommended target outcome is VCC plus model-driven semantic compaction plus bounded pruning: shift the old static 60% auto-trigger into a soft LLM nudge/tool affordance, and keep a higher hard automatic backstop around 80% for safety. Commit-aware recovery is deferred for this pass.

Non-goals

  • Do not disable the existing vendored VCC path.
  • Do not add a full external memory database or background dreamer process.
  • Do not broaden compaction into unrelated Pi workflow changes.

Current baseline

  • _pi/packages/pi-vcc is vendored from sting8k/pi-vcc, locally versioned as 0.3.6-ai-configs.1, and reviewed through upstream 0.3.15.
  • _pi/extensions/percentage-compaction.ts proactively triggers pi-vcc at a 60% context threshold and blocks fallback to unsafe default compaction when pi-vcc is missing.
  • Local deltas include the manual bypass marker, agent-only fallback tail, tool-result boundary safety, continuation after in-flight compaction, and final redaction preservation.

Phase 2 — SelfCompact-style semantic timing

Replace the static 60% auto-trigger with a SelfCompact-style model-controlled path. The model should decide when to compact at semantic boundaries, while the runtime retains a higher hard backstop to prevent overflow.

Recommended thresholds

  • COMPACTION_NUDGE_PERCENT = 60: soft nudge only. Do not auto-compact here.
  • COMPACTION_STRONG_NUDGE_PERCENT = 75: stronger nudge and status warning. Still do not auto-compact solely because of this threshold.
  • HARD_AUTO_COMPACTION_PERCENT = 80: runtime safety backstop. Auto-compact at this level even if the model has not chosen to compact.
  • FAILURE_DELAY_TURNS = 1: suppress soft nudges immediately after fresh failure output so the model can use the evidence before being asked to compact.

Model-driven compaction tool

  • Register an LLM-callable compact_context tool from _pi/extensions/percentage-compaction.ts using pi.registerTool.
  • Tool parameters: reason (required short string), preserve (optional short instructions), and boundary enum such as subtask_complete, before_topic_switch, after_test_loop, manual_recovery.
  • Tool guidance shown to the model through promptSnippet / promptGuidelines: use compact_context after a subtask resolves, before switching topics, after a test/debug loop has been interpreted, or when context is becoming noisy; do not use it mid-tool-chain, mid-derivation, immediately after fresh failure output, or while critical raw evidence has not been summarized.
  • compact_context does not call ctx.compact directly from inside tool execution. It records pendingModelCompaction = { reason, boundary, preserve, requestedTurn, toolBatchId, sawSiblingTools }, returns a tool result saying compaction is queued for a safe boundary, and lets the turn_end state machine trigger compaction only after the tool result has been delivered and sibling tool-output safety is satisfied.
  • When the queued request is executed, pass custom instructions as PI_VCC_MANUAL_BYPASS_MARKER + "\n" + JSON.stringify({ source: "compact_context", reason, boundary, preserve }) so the bypass marker still works and pi-vcc receives the model’s intent.
  • Update pi-vcc session_before_compact / summary input handling to parse the JSON payload after the marker. The reason, boundary, and optional preserve become a short [Compaction Intent] note in the generated VCC summary. If preserve is absent, omit it; if malformed, ignore only the JSON payload and keep the marker bypass behavior.
  • The tool remains available below 60% for explicit model judgment, but nudges should normally start only at 60% to avoid unnecessary early compaction.

Model-visible nudge delivery

  • Soft/strong nudges must be LLM-visible, not only operator UI notifications. Use pi.sendMessage({ customType: "compaction-nudge", content, display: true, details }, { deliverAs: "steer", triggerTurn: true }).
  • Use deliverAs: "steer" so nudges are delivered after the current assistant turn finishes tool calls and before the next LLM call; this avoids interrupting an active tool chain while still reaching the model.
  • The nudge content must name compact_context, current usage band, hard backstop threshold, and the semantic-boundary rubric. It must say that 60%/75% are nudges only and not instructions to compact immediately.
  • Rate limiting: send at most one soft nudge per crossing into the 60–74% band and at most one strong nudge per crossing into the 75–79% band. Reset the band after successful compaction or after usage drops below that band.
  • Use ctx.ui.notify only as a secondary operator-visible mirror; tests must prove the model-visible sendMessage path fires.

Runtime state machine

  • Add module state in _pi/extensions/percentage-compaction.ts: lastNudgePercentBand, lastNudgeTurn, pendingModelCompaction, lastAutoCompactionPercent, lastFailureTurn, and existing compactionInFlight.
  • On each turn_end, increment a local turn counter before evaluating state.
  • Below 60%, show no automatic nudge and never auto-compact solely from threshold logic.
  • If pendingModelCompaction exists and the triggering assistant tool batch contained only compact_context, the first post-tool turn_end may trigger pi-vcc compaction with the marker+JSON custom instructions, then clear pending request on completion/error. Do not also emit a soft/strong nudge on that same turn.
  • Mixed tool-batch guard: if compact_context was called in the same assistant message as any sibling tool call, do not compact on the immediate post-tool boundary. Defer until a later completed assistant/non-tool boundary after the model has had a chance to interpret sibling tool outputs. This prevents compaction before fresh sibling evidence is summarized.
  • At or above 60%, send a model-visible soft compaction nudge at most once per band crossing, telling the model that compact_context is available when it reaches a safe semantic boundary.
  • At or above 75%, send a model-visible stronger nudge and status warning, but still leave the decision to the model unless 80% is reached.
  • At or above 80%, trigger pi-vcc compaction automatically as the hard backstop, preserving existing in-flight continuation and tool-call boundary safeguards.
  • Detected failure output means the immediately preceding completed tool result or assistant-visible result contains failure markers such as nonzero exit, failed, error, exception, or test-failure summaries; soft/strong nudges wait for FAILURE_DELAY_TURNS, but the 80% hard backstop still applies.
  • Stale-percent ratchet: after a successful hard backstop compaction or an "already/nothing to compact" result, record the exact percent; suppress repeat auto-compaction while usage percent is unchanged.
  • session_before_compact keeps the missing-pi-vcc guard, manual bypass handling, stale-percent guard, and overflow-retry behavior from Phase 1.

Manual behavior

  • /compact-now remains an immediate human/operator bypass through pi-vcc.
  • The model should prefer compact_context; humans can still use /compact-now.

Phase 3 — DCP-style cheap pruning before VCC summary

Add low-risk deterministic pruning before summary rendering. The pruning must never mutate persisted session history; it only changes what enters the compacted summary.

Insertion point

  • Add a small deterministic pruning stage after normalization/noise filtering and before buildSections / brief rendering, so persisted session JSONL remains untouched.
  • Keep the current kept tail unpruned. Pruning applies only to the portion being summarized.

Locked pruning rules

  1. Repeated tool-call dedup: compute a stable key from normalized tool name plus canonical JSON arguments. For duplicate keys, preserve the newest tool call/result pair and replace older result content with [Older duplicate tool result pruned; latest result kept at #N]. Keep the older tool call identity and arguments summary.
  2. Errored tool input pruning: after ERROR_PRUNE_AFTER_TURNS = 4 summarized turns, prune bulky failed-tool input payloads over ERROR_INPUT_PRUNE_THRESHOLD_CHARS = 2000. Preserve tool name, command/argument summary, nonzero/error status, and first error line.
  3. Large output caps: cap repeated search output and package-manager logs to MAX_PRUNED_TOOL_RESULT_CHARS = 1200 while retaining first real error, final status line, and file paths. Existing VCC brief caps remain the fallback for non-pruned outputs.
  4. Protected outputs: never prune user messages, current kept tail, explicit plan-review outputs, subagent final results, todo state, compaction summaries, or outputs from tools classified as protected in tests.

Required pruning tests

  • Duplicate tool calls retain the latest result and replace only older result content with the locked placeholder.
  • Errored tool input pruning preserves command identity and error evidence.
  • Protected outputs and kept tail entries are not pruned.

Phase 4 — Commit/git-aware durable context — deferred

Deferred after implementation review: bounded [Commits] extraction added substantial parser complexity and ambiguous git-output failure modes without clear enough product value for this pass.

  • Do not emit a [Commits] section from VCC summaries in this plan.
  • Remove local commit extraction wiring and tests from the active implementation scope.
  • Keep commit details recoverable through existing transcript/recall surfaces instead of promoting them into durable summary headers.

Acceptance criteria

  1. VCC remains the default compaction path for Pi in this repo.
  2. Crossing 60% or 75% does not auto-compact; it sends a rate-limited model-visible pi.sendMessage nudge toward using compact_context at a safe semantic boundary.
  3. The model can invoke compact_context for queued semantic-boundary compaction, the marker+JSON intent is preserved into VCC summary input, and the 80% hard backstop still protects against context overflow with overflow retry behavior reconciled with upstream 0.3.18.
  4. Repeated tool outputs and stale errored inputs are compacted deterministically without losing command identity or latest evidence.
  5. VCC summaries do not emit a commit-extraction section; commit details remain recoverable through transcript and recall surfaces.
  6. Existing recall, redaction, fallback-tail, and in-flight continuation tests continue to pass.
  7. Upstream drift metadata and scripts/check-pi-vcc-upstream.sh agree with the reviewed upstream commit.

Verification

This is a high-risk context-management change. Verification must include deterministic unit coverage, install validation, and several end-to-end Pi sessions that exercise real compaction behavior over time. Do not claim implementation success from package tests alone.
