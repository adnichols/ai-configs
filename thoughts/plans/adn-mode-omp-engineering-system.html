Product-owner context

OMP currently has strong specialist roles and rigorous planning, review, and delivery workflows, but it lacks one coherent opt-in mode that applies those capabilities to everyday investigations, bug fixes, features, refactors, prototypes, performance work, autonomous runs, and shipping. The operator reviewed pstack because its central router, explicit playbooks, model-diverse councils, real-artifact verification, and concise engineering principles offer a stronger default for agentic development than assembling those behaviors manually each time.

Why now: a 21-day audit of 36 ai-configs OMP sessions found 3,603 tool calls, 52 compactions, 24 operator aborts, repeated review loops, recurring manual role/model changes, repeated multi-host rollout work, and only modest structured delegation. The evidence supports a system that keeps correctness first while lowering operator intervention, protecting context, and making parallel work reviewable.

Key conclusion: this is an operator-facing agent-workflow change, not an application-runtime defect. It adds an OMP-native engineering mode and a complete experimental skill set. It retains current plan, delivery, and completeness workflows. Ponytail is the only immediate retirement; autoreview remains until a ten-change comparison supports a replacement decision.

What’s new — one rigorous OMP mode from request to proof

Promise: after the operator invokes /adn-mode, OMP will choose a named playbook, apply the relevant engineering principles, route work through semantic roles, verify the real artifact, and remain active for that session without requiring the operator to restate the workflow.
  • Before: the operator chooses individual skills, reviewers, plans, and verification approaches; model-role changes and parallel investigation are often assembled manually.
  • After: ADN selects the playbook and ownership shape, automatically invokes required skills, uses the Grok/Kimi councils when warranted, and records evidence in a consistent form.
  • Observable result: the operator can invoke one command, inspect visible playbook todos and principle-driven decisions, and receive a verified outcome or a truthful blocker.
  • Preserved guarantees: Delivery stays explicit opt-in, completeness stays request-bound, repository rules still constrain ownership and authority, and no deployment, customer message, customer-facing system change, or third-party repository action becomes implicitly authorized. Exact explicit authorization can bring the named action into scope.

Goal

Install a complete, attributed, OMP-native ADN engineering system into the live OMP and Agent Skills directories; make it sticky, role-routed, testable, and reversible; retain current OMP workflows during evaluation; remove Ponytail cleanly; and produce enough aggregate evidence over ten representative changes to decide whether ADN review should replace autoreview.

Decision Attention / Low-confidence Areas

No product decision required. The operator completed a six-round design interview and explicitly requested execution-readiness review. All product-shaping choices are locked below.
  • Extension behavior: OMP documents the required command, custom-entry persistence, before_agent_start injection, branch/tree reconstruction, and compaction events. The implementation must still prove the exact sticky-state behavior against OMP v18.0.6.
  • Review replacement: the outcome is intentionally unknown until the ten-change trial. INCONCLUSIVE is an accepted truthful result and must include exact manual experiments.
  • Shared skill visibility: ADN skills may be visible to other harnesses through ~/.agents/skills. This plan does not refactor those harnesses or claim parity there.

Why this plan exists

The current system already contains useful pieces: OMP semantic model roles, named planner/reviewer/oracle/completeness agents, task fan-out, a todo tool, direct TDD guidance, product principles, integration-integrity checks, Doct-reviewed plans, and a delivery ledger. The missing layer is a cohesive opt-in router and common engineering doctrine for ordinary work. Copying pstack wholesale would preserve Cursor assumptions that OMP does not share. Rebuilding every current workflow would duplicate stronger local guarantees. The selected design translates behavior, reuses proven OMP capabilities, and keeps replacement decisions evidence-based.

The transcript audit also separates product problems from habits. Multi-host rollout already has a script and should not become prose. Skill parity belongs in tests. Repeated manual scout decomposition should become how/swarm routing without removing Scout. Role changes need setup-adn. Transcript mining needs an aggregate-only audit. External skill adoption needs one provenance-aware workflow.

  • ~/.agents/skills is the shared one-level Agent Skills root. OMP discovers name/description metadata and resolves bodies through skill://name.

Locked decisions

  1. Translation: ADN is OMP-native. Pstack supplies behavior and vocabulary, not Cursor runtime assumptions.
  2. Priority: correctness, agentic development, and low operator reliance precede speed or raw fan-out.
  3. Activation: explicit once, then sticky for the current session; new sessions are inactive. Casual turns preserve state but do not run routing or automatic skills.
  4. Authority precedence: system/runtime constraints win, then the explicit operator request, then repository guidance not explicitly overridden by that request, then ADN defaults. ADN proceeds with authorized in-scope local, repository, GitHub, ticket, internal communication, merge, and history-rewrite actions. Destructive data operations pause only when the exact operation and scope were not explicitly preauthorized; matching preauthorization proceeds without another stop. Credential/permission changes and deletion of work not proven merged or abandoned remain pause classes. Customer messages, deployments, customer-facing instance/system changes, and third-party repository actions are default-excluded but become eligible when the operator explicitly names the action and scope; third-party authority must name the exact repository and action.
  5. Implementation ownership: every code playbook records an ownership decision. The parent keeps tiny surgical fixes. One implementation owner handles coherent non-trivial changes where repository rules permit. Parallel writers receive disjoint surfaces. Repository-specific ownership rules override ADN defaults.
  6. Architecture: skip Architect for a local implementation detail that does not cross a meaningful boundary; use singular architect-grok for bounded precedent-backed design; run both architect agents for novel, contested, ownership-moving, public API/schema/persistence/concurrency/module-boundary, or expensive-to-reverse choices.
  7. Cross-judging: Arena uses both architects independently. Interrogate uses the existing Grok reviewer plus a Kimi reviewer.
  8. Models: architect Grok = Grok 4.6 high; architect Kimi = Kimi K3 Max max; Kimi reviewer = Kimi K3 Max high; existing reviewer remains Grok 4.6 high.
  9. Principles: all 21 remain directly invocable and indexed inline. Laziness Protocol replaces Ponytail immediately. Final replies name every applied principle and the decision it changed.
  10. Automatic triggers inside active ADN: only on non-trivial work, select one direct playbook, apply relevant principles, run how for uncertainty, apply the Architect threshold, use the tdd adapter when a cheap behavior gate exists, verify the real surface, apply no-comments/unslop/technical-writing, and load typescript-best-practices on TypeScript surfaces.
  11. Explicit-only operational skills: arena, swarm, interrogate, recall, reflect, automate-me, adopt-skill, bro, show-me-your-work, setup-adn, and adn-audit. why, teach, and blast-radius are playbook-routed unless directly named by the operator. figure-it-out is the active-router fallback. Outside active ADN, no router runs silently and any named skill remains directly invocable.
  12. Explicit-only playbooks: Babysit, Shipping, Autonomous run, Orchestrate, Autopilot full, Autopilot stack, Session pickup, Pause safely, Worktree cleanup, and Opening a PR require operator wording that names the outcome. Multi-phase plan is also selected by any of the six formal thresholds and only adapts into the existing reviewed-plan/run-plan flow.
  13. Verification-skill threshold: first use an existing repeatable real-surface command, otherwise a one-off real smoke. Create a project-local verification skill only when current acceptance needs repeatable multi-step proof no existing command supplies, or the same uncovered path appears in two distinct recorded tasks. Maintain one only when the changed production surface is already in its declared coverage and its driver no longer proves that surface. Otherwise record “no skill created/changed” and the smoke evidence.
  14. Self-healing boundary: a loaded /adn-mode command may reconcile deterministic drift in roles, shared skill links, agent links, and its generated profile-local wrapper, then retry. It cannot bootstrap a command missing at process start; that state fails with bun ~/.agents/adn/scripts/setup-adn.ts apply. Ambiguous collisions and post-install user drift fail closed. ADN serializes its own writers; setup/rollback require no concurrent external omp config or interactive settings mutation because v18.0.6 exposes no public atomic compare-and-swap for the whole record.
  15. Comments: remove narration. Keep required API docs and short non-obvious reasons, constraints, or invariants.
  16. Existing workflows and formal-plan threshold: retain planning, delivery, completeness, integration integrity, and safe Git index behavior. Route to the existing reviewed-plan/run-plan path for multi-PR or cross-repository work; expensive schema, persistence, or public-API migration; work expected to exceed one agent session; unattended work requiring an audit trail; work spanning several production subsystems; or an explicit plan/delivery request. Bounded investigations, bugs, features, refactors, and prototypes stay direct and never arm Delivery implicitly. Evaluate only the implementation-review gate.
  17. Installation: author into live OMP/Agent paths first. A later broad capture into ai-configs is separate. The narrow Ponytail installer/test removal is included now.
  18. Review replacement: ten blinded changes; no automatic winner. Report INCONCLUSIVE with structured discriminating experiments when evidence does not support a judgment.
