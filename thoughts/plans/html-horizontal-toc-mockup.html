This mockup keeps the reviewer-friendly dark theme and stable anchors, but removes the left navigation rail. The table of contents sits near the top as a horizontal, responsive, multi-column section; every plan section below it gets the full document width.

Status

Format decision: ToC becomes a near-top horizontal card, not a left rail.
Review target: Check whether the ToC is high enough and whether four groups are the right density.

Goal

Update HTML plan guidance so generated plans preserve navigation without wasting horizontal space. The plan body should use the full readable width for tables, BDD scenarios, phase detail, and screenshots.

Why this plan exists

The current default two-column reviewer layout pins a table of contents on the left. That works for very long plans, but it leaves unused space next to every section and makes wide plan content feel cramped. A top ToC keeps links discoverable while letting all later content span the full page width.

Authority and inputs

  • User request to move the ToC out of the left side of the plan.
  • Existing dark-mode HTML plan requirements.
  • Example plan-review page showing a horizontal ToC direction.

Current implementation reality

The repo guidance currently instructs agents to use a left sidebar/table of contents for HTML plans. This mockup demonstrates the replacement pattern those prompts should describe.

Progress

Product intent alignment

The reviewer should land on the document title, see status immediately, and then get compact navigation before reading the full-width plan. The ToC is intentionally close to the top instead of buried after several sections.
