## Pre-review scope baseline

### Intended behavior

Add an always-available, read-only Oracle that uses GPT-5.6 Sol at high reasoning with inherited/forked parent context. Make it available through direct `Agent` invocation and `/consult:oracle`, and teach planning, delivery, execution, and bounded review-escape workflows when Oracle consultation is appropriate. Oracle advice remains advisory; the driving agent retains implementation and decision authority, and existing planner/reviewer/PM/completeness gates remain intact.

### Supported paths

- Direct `Agent` calls with `subagent_type: "oracle"`.

- Delivery/review workflow references in the touched prompt and skill files.

- Routine discovery, ordinary implementation choices, and standard readiness/code review do not require Oracle consultation.
- This change does not perform the separate full migration from `@tintinweb/pi-subagents` to nicobailon's orchestrator.

## Cycle 1 finding and triage

| Finding | Reviewer | Severity | Scope | Decision | Evidence |
|---|---|---:|---|---|---|
| Oracle frontmatter did not make the requested Sol-high/fork-context contract executable across the current tintinweb runtime and nicobailon-style configuration | Active-harness `reviewer` | P1 | IN_PLAN | Fixed | The current tintinweb parser consumes `thinking` and `inherit_context`, while the requested nicobailon approach uses `thinking` and `defaultContext: fork`. The initial definition relied on repository `reasoningEffort` plus only the current context key, so at least part of the promised high/forked behavior would be ignored depending on runtime. |

Trigger and reachable path: invoke the newly added Oracle through the installed subagent runtime; the runtime parses `_pi/agents/oracle.md`; unsupported frontmatter keys are ignored. Observable impact: Oracle could inherit the caller's default thinking rather than run at high reasoning, or lose fork-context behavior after the planned orchestrator migration, contradicting the accepted Oracle contract. Diff relationship: the failure was introduced directly by the new persona configuration.

Smallest fix at the existing ownership boundary: retain the repository policy marker and add both runtimes' executable keys in `_pi/agents/oracle.md`:

```yaml
reasoningEffort: high
thinking: high
defaultContext: fork
inherit_context: true
```

`_pi/README.md` now explains the compatibility intent, and the roster test requires all four fields. No protocol or ownership expansion was needed.
