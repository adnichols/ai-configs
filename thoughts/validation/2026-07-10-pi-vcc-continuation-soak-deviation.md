# Pi VCC continuation rollout validation boundary

The rollout gate in `scripts/run-pi-vcc-continuation-soak.sh` runs in isolated `PI_CODING_AGENT_DIR`, session, and log directories. It imports the selected source or installed package and instantiates that candidate's real `createContinuationCoordinator` with a host-faithful `ExtensionAPI`, `EventBus`, session branch, lifecycle-handler, and timer mock. It drives real coordinator `request`, persistence reconciliation, wake listeners, retry/deadline callbacks, `sendMessage`, consumption/progress/settlement, replacement, and reload behavior. It also imports and executes the selected standalone `percentage-compaction.ts` extension far enough to prove terminal `/compact-now` request-before-wake ordering and persisted request/outcome wire parity.

The fault matrix covers void send with no consumption, synchronous send throw and bounded retry, matching consumption/progress/settlement, error and abort retry, lost/duplicate wakes, multiple pending request order, unrelated tool completion safety, correlated persisted safety-ready wake, session replacement, reload listener restoration, and at least ten terminal coordinator transactions.

A provider-backed Pi model process is intentionally not claimed: the required rollout command is no-network/provider-free and Pi 0.80.6 does not expose a credential-free stub provider CLI for lifecycle injection. The gate therefore verifies the selected shipped extension code through its public host contract rather than calling pure transition functions as the primary soak. Installed mode fails closed if either installed candidate path is absent and never silently substitutes source.
