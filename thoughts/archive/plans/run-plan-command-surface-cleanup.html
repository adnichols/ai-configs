Run Plan Command Surface Cleanup

Rename the current scoped plan execution skill to an ergonomic non-conflicting command, preserve plan-reviewer button behavior, and explicitly inventory low/no-use commands and skills for archive recommendations.

Status: execution-ready (GPT and GLM cleared) Plan path: thoughts/plans/run-plan-command-surface-cleanup.html Repo: ai-configs UI impact: text-only command/docs surface

Goal

Replace the user-facing scoped-plan-run skill name with the shorter, unique run-plan naming family so it no longer collides with Pi's built-in /scoped-models command. Keep existing plan-reviewer action buttons working by preserving their bridge skills while updating the bridge implementation to call the renamed runner.

The plan must also make the command/skill archive inventory explicit enough for a reviewer to approve, reject, or reclassify each candidate later. The default implementation does not delete or move detritus commands beyond the requested scoped-plan-run rename/deprecation cleanup.

Decision Attention / Low-confidence Areas

D1 — Archive deletion is deferred by default. The inventory below ranks archive candidates and recommends disposition, but this execution plan only removes the old scoped-plan-run installed surface as part of the requested rename. Other detritus commands/skills stay in place unless a browser-review comment or explicit user message approves an exact per-item archive/delete/rename action.

D2 — No compatibility alias for scoped-plan-run. Keeping an alias preserves the autocomplete collision. This plan therefore removes the old installed skill surface after migration rather than keeping a long-lived alias.

D3 — Existing plan-reviewer local config may override defaults. The source default uses plan-reviewer-build, but a local database could be configured to emit another skill name. Verification must inspect or reset the local Build Plan skill setting if needed.

Why this plan exists

The current full-PR scoped execution workflow is installed as /skill:scoped-plan-run. In Pi, typing /scoped... also surfaces the built-in /scoped-models command, which makes the command hard to invoke quickly. A rename is safe only if the surrounding command surfaces, installer cleanup, plan-reviewer browser action comments, and documentation all agree on the new name.

  • User request: rename @skills/scoped-plan-run/ to a unique shorter command such as /run-plan, inspect command usage, identify detritus to archive, choose a non-conflicting naming strategy, and protect plan-reviewer button behavior.
  • Pi docs: skills invoke as /skill:name; direct slash commands come from prompt-template filenames or extensions.
  • Plan-reviewer source evidence: src/schemas.ts defaults action button comments to plan-reviewer-execution-ready and plan-reviewer-build; src/server/app.ts emits Use the ${skillName} skill for this plan.

Non-conflicting naming strategy

Canonical full lifecycle: /run-plan <plan> for ergonomic Pi use and /skill:run-plan <plan> for explicit skill use.

Browser action bridge: keep plan-reviewer-build and plan-reviewer-execution-ready because those names describe service-originated comments, not the underlying runner.

Direct execution-only: keep /dev:run <plan> for the narrower phase execution path.

Handoff wrapper: update /cmd:execute-plan and plan-mode prompts to offer /run-plan for full implementation-through-PR and /dev:run for direct execution-only.

Avoid: new user-facing names beginning with scoped-, because Pi already owns /scoped-models.

Locked decisions

  • Use run-plan as the new runner name. It is short, verb-first, and currently free across checked Pi prompt, shared skill, and installed skill surfaces.
  • Do not keep scoped-plan-run as an installed alias. The old name should be cleaned by installer deprecation logic to remove the autocomplete conflict.
  • Keep plan-reviewer-build as the Build Plan button skill. The service button should remain stable and delegate to run-plan.
  • Default archive behavior is documentation-only. The first pass records archive recommendations and follow-up decisions, but does not remove old low/no-use commands unless explicitly approved.

  2. /skill:run-plan exists, /skill:scoped-plan-run is no longer installed after running the repo installer, and repo references to the old skill are gone except historical plan logs.
  3. Plan-reviewer Build Plan action comments still say to use plan-reviewer-build, and that skill delegates to run-plan.
  4. The archive inventory is committed in docs or an archival manifest with high-confidence, medium-confidence, and keep categories, so future agents do not need to rediscover the same usage data.
  5. No low/no-use detritus command or skill is deleted in the first pass without explicit approval; high-confidence, medium-confidence, and keep candidates remain visible in a durable follow-up inventory.
  6. /cmd:execute-plan, Pi plan-mode prompts, and README guidance present non-conflicting choices: /run-plan for full lifecycle and /dev:run for direct execution-only.
