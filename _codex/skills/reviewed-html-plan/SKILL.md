# Reviewed HTML plans

Use this workflow only when Doct publication or review is requested. A generic request to review a local plan stays local. Plan-only work authorizes plan edits, not product implementation or a delivery ledger.

1. Read planning-workflow and [preparation and browser feedback](references/browser-review.md). Create or update the scoped HTML plan, publish through doct-document-ops, and follow its listener requirements before handing off the browser URL.
2. Process ordinary feedback within scope. Quiet listeners and resolved comments do not authorize readiness review. Start PM and independent planner readiness review only on the user's explicit instruction or Doct's explicit execution-ready action.
3. For that readiness request, read [readiness review](references/readiness-review.md). The author integrates findings; an independent native planner must supply the final PLAN_EXECUTION_READY verdict after material edits. Do not self-certify.
4. Synchronize the actual plan and Doct metadata. Report unresolved product decisions or missing evidence truthfully. Stop before implementation unless it is already authorized, then continue through the native Codex execution workflow.

Use bounded reviews and targeted rereviews within the reference's convergence limits. Never arm or advance an OMP/Pi delivery ledger from this Codex workflow.
