# Multi phase plan

Read the parent skill and [Codex runtime contract](../references/codex-runtime.md).

For planning, use `planning-workflow` and create one executable source plan with phases that each deliver a complete verifiable outcome. Ground command names and boundaries in the repository. Keep post-merge operations explicit and non-blocking for PR creation. For implementation of an existing plan, use `run-plan` when a through-PR lifecycle was requested, otherwise execute the authorized phases directly. Track truthful progress and preserve source authority. Do not arm an OMP/Pi delivery ledger from Codex.
